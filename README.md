# 摺痕推理 Lab / Fold Logic Lab

一個不需要登入、沒有框架相依的靜態練習網站。它模仿「看折紙步驟、選出攤平後的完整摺痕圖」這類題目的核心：**不是憑視覺拼湊線條，而是從真正的折疊操作推導每一條摺痕。**

## 開啟方式

此版本使用 ES Modules，請以本機伺服器開啟（而不是直接雙擊 HTML 檔）：

```bash
cd /home/user
python3 -m http.server 4173
```

然後前往 <http://localhost:4173>。

## 出題方式：模仿原圖真正的推理結構

原圖不是「猜哪張圖看起來像」；它的結構是：

1. 從完整方紙開始，依序把紙折成越來越小、層數越多的形狀。
2. 每次折紙都在**當下所有重疊紙層**上留下摺線。
3. 把紙攤回原方形時，晚一步的折線會透過更早的折軸，回到每個鏡像對應位置。
4. 正確選項必須同時保留早期基準摺線、後期折線的數量、位置、端點與鏡像關係。

每一題會以新的 10 字元 seed 動態建立折紙程式；seed 空間有 `34¹⁰` 種可能，並非從固定題庫抽出圖片。生成器只接受「小的一側完整折到大的一側」的操作，並以模擬器驗證每一條摺線均回映在原方紙內。公開題目會採用與參考圖相同的**首折斜向**或**局部角落折**語法；角落折的折軸是「角 → 內部點」的垂直平分線，只影響一個小三角角片，而不是整張紙對半。生成器另限制角落折後的 A 面積不得超過折前紙包的 30%，避免小角片被誤畫成整個側邊傾斜的梯形。

| 難度 | 結構差異 | 主要推理負荷 |
|---|---|---|
| 起步 | 3 折：近中央對半 × 2 + 斜折 | 學習兩個鏡軸如何把斜線複製成四份 |
| 進階 | 4 折：偏心對半 × 2 + 斜折 + 窄邊折 | 端點到偏心軸的距離、最後短線的回映位置 |
| 菁英 | 5 折：兩組偏心對半 + 16 層後的斜折 | 多個不等距鏡軸、16 個斜線副本、接近正解的干擾選項 |

`paper-fold-engine.js` 實作平面折紙模型：每一層都保存「目前折疊平面 → 原始方紙」的仿射映射與每一步的面片歷史。每次操作會把紙面多邊形切成 B（保留側）與 A（移動側），將 A 鏡射至 B 上並保留映射；最後把每層的摺線映射回原方紙。Sequence 圖直接使用這些面片歷史畫出 B 與精確落在其上的 A，而非以外接凸包偽造剪影。因此，**正解與折紙圖都是模擬器的輸出，不是獨立繪製的圖。**

### 參考題的出題技巧如何轉入生成器

參考題的好處不在於「線很多」，而在於它把一個複雜變化拆成容易閱讀的視覺節奏：先以斜向／角落動作建立明顯的 V 或屋頂 motif，再以對半折壓縮紙包，最後在小紙包上產生局部折線。選項則共用一部分基準摺痕，但把一整組斜線 motif 放在不同區域或方向，而不是只有一條線差一點點。

因此生成器現在不再只有單一 diagonal cascade，而是從三個都以斜折開頭的合法折法語法中取樣：

| 折法語法 | 視覺 motif | 主要變化 |
|---|---|---|
| Diagonal cascade | 對角斜帶 | 斜折後逐層對半、偏移斜折 |
| Kite cascade | V／菱形 | 斜折、軸折與交叉對角折交替 |
| Gate roof | 屋頂／閘門 | 兩組對角折先形成交叉頂點，再壓縮為小紙包 |
| Corner roof | 局部角片／雙屋頂 | 從角落折到內部 1/4–1/2 區域，先建立小三角角片再對半壓縮 |
| Mixed direction | 流動折法 | 每一步從上→下、下→上、左→右、右→左、對角折與局部角落折中隨機選擇；對半、1/3、1/4 與偏心比例皆可能，且只接受模擬器驗證通過的方向與比例 |

三種語法都由相同模擬器驗證，並在難度升高時加入偏心軸與更晚的折疊；它們創造的是不同的摺痕「家族」與拓撲，而不只是旋轉同一張圖。

## 題目碼重現

每題右上角都顯示像 `FL-N-ABCD234567` 的題目碼。點選右上角齒輪，將題目碼貼到「重現題目」欄位後按 **載入**，網站會同時還原：

- 難度（`S` 起步、`N` 進階、`X` 菁英）；
- 完整折法與所有 SVG 摺線；
- 正解位置與 5 個選項的排列順序。

因此同一題可被分享、回放或加入錯題練習，而不會因為重新載入頁面而變成另一題。

## 題目圖與選項的視覺規則

題目圖與選項刻意使用不同、但一致的視覺語言：

### 折紙步驟圖

- 黑色粗實線只表示**紙張可見外緣**。
- 黑色虛線加黃色箭頭表示**下一個要執行的折軸與移動方向**。
- 每個已完成的折紙狀態都以兩層顯示：固定在相同左下基準位置的綠色 **B（底層）**，以及精確落在其上的 **A（頂層）**。兩層採同一紙色系，僅以 A 的細黑實線邊界與極淡陰影區分；黃色虛線與箭頭只保留給「下一折」，完全遵循參考圖的視覺文法。

這遵守 origami 圖示的基本原則：可見紙邊使用粗實線、折軸與移動方向用一致的線與箭頭；複雜的多層動作應呈現移動紙片相對靜止紙片的關係，而非只畫出最後剪影。[Origami Diagramming Conventions](https://langorigami.com/article/origami-diagramming-conventions/)

### 答案選項

選項只是在問「攤平後留下哪些摺痕」，並沒有提供 mountain／valley 資訊。因此：

- 外框一律是粗實線，且只表示紙張邊界；
- **所有內線一律使用同樣粗細、同樣深色、同樣虛線樣式**；
- 不使用中心點、顏色、粗細或實線／虛線混搭，暗示哪一條較早、較晚、較重要或較可能正確。

這避免把 origami 教學的 mountain／valley 記號錯誤套進本題型；在標準 origami 圖示裡，dash、dash-dot 與實線本來有不同意義，題幹未定義就不應混用。[Yoshizawa–Randlett system](https://en.wikipedia.org/wiki/Yoshizawa%E2%80%93Randlett_system)

## 出選項方式

五個選項都與正解有**相同的可見摺痕段數**與同樣的線條格式；不再使用「少幾條線」這種容易排除的干擾，也不使用「把某條線往旁邊偷移一小格」的近似陷阱。正解以外的四個選項，是從完整錯誤折法或大範圍錯誤鏡射產生：

1. **錯誤逆向鏡軸**：把後段摺痕以錯的水平或垂直軸展開。
2. **錯誤展開順序**：把晚期摺痕多做一次半轉，等同把倒序還原方向弄反。
3. **錯誤對角軸家族**：把某一分支誤認成另一條對角鏡軸。
4. **局部分支鏡射錯誤**：只把某一組同層副本套到錯軸，模擬「一部分追對、另一部分追錯」的真實心像失誤。

每一張選項在繪製前還會合併「相接且共線」的同一條物理摺痕，避免由多層回映造成不自然的斷裂虛線；真正有空隙的兩段線則不會被錯誤接起。生成器會拒絕重複選項、視覺線段數不同的選項、與正解幾何上相同的選項，以及與正解平均距離小於 **7 SVG units** 的近似選項；候選彼此平均距離也至少是 **4.5 SVG units**。同時每個誤答都必須保留至少 1/4 的共用基礎摺痕，避免整張圖被翻到完全無關的位置。這使玩家需要判斷的是「共用基準下，哪一個大範圍摺痕家族被放在錯的對稱位置」，而不是猜某條線只差一個小格。紙張折疊研究也將「少想像展開某一次折」列為可辨識的常見錯誤策略；本作保留其推理本質，但讓所有選項的視覺複雜度相當。[Knowing when to fold 'em](https://www.sciencedirect.com/science/article/abs/pii/S0191886918304495)

## 已完成的功能

- **程序化無盡題組**：每次以新的 10 字元 seed 產生合法折紙程式、正解與 5 個近似干擾選項；seed 可重現，題目不依賴固定圖片題庫。
- **真實折疊狀態圖**：從原方紙到最終小疊，折線與箭頭直接取自同一組操作資料；每一個完成折都顯示 A 頂層覆在固定位置的 B 底層上。所有卡片使用同一個 76-unit 世界尺度與 B 左下基準點，因此折後小紙包會保持真實縮小比例；每張卡片都有固定高度的圖像槽與 caption 槽，文字換行不會推擠圖像或箭頭。滑鼠移到圖上或鍵盤聚焦時可放大檢視，不會犧牲幾何比例。題目中不透露層數或其他文字資訊。
- **逐步解答**：只顯示目前步驟與已經揭示的摺痕；未來步驟的線段不會以預覽、淡線或任何形式提前出現。
- **逐步呈現模式（可選）**：在逐步解析可勾選「依折序上色」，讓每一折保留自己的顏色；也可勾選「聚焦本步新增」，以高對比色突出本步線段並淡化先前摺痕。兩個模式可獨立或合併使用，且都有文字圖例。
- **有效回饋**：答錯後指出應檢查副本數量、端點或鏡軸，而非只說對錯。
- **難度模式**：起步、標準、挑戰（挑戰模式減少預覽線索）。
- **進度紀錄**：以 `localStorage` 保存在目前瀏覽器，包含完成題數、一次答對、連對與最佳紀錄；不使用帳號或追蹤。
- **鍵盤與行動裝置支援**：選項可用 Tab 選取，再以方向鍵切換；清楚的焦點樣式、符合觸控尺寸的按鈕、響應式版面與減少動態效果開關。
- **可及性圖像策略**：所有摺紙與摺痕圖都使用原生 SVG，不以 Canvas 繪製；SVG 有可讀標題，互動元件則使用真正的按鈕與狀態標記。

## 摺痕正確性與防溢出設計

- `puzzle-data.js` 是難度設定、seeded 程序生成器、正解、干擾選項與解說的單一資料來源。
- `paper-fold-engine.js` 計算原始方紙上的每一條摺痕；單元測試會逐線比對結果與正解選項。
- SVG 方紙座標嚴格限制於 `8–92`；原本超出右側紙張的 `97` 已修正。
- 每張 SVG 再以 `clipPath` 包住內容，筆觸的圓角端點也不會越過黑色方紙外框。
- 裝飾膠帶已收回容器範圍，避免造成整頁水平捲動。

## 設計與技術依據

這個作品在製作前參考了以下資料，並將其轉成實際介面決策：

1. [W3C WCAG 2.2 — Target Size (Minimum)](https://www.w3.org/TR/WCAG22/#target-size-minimum) 與 [Focus Appearance](https://www.w3.org/TR/WCAG22/#focus-appearance)：互動目標保留足夠面積、使用高對比且不被遮住的鍵盤焦點；網站沒有要求拖曳才能操作。
2. [MDN：Canvas API accessibility](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Basic_usage#accessibility)：Canvas 內容不會自然暴露給輔助科技，因此圖形改以原生 SVG 和語意化 HTML 呈現。
3. MathBits Notebook 的 [Constructions with Folded Paper](https://mathbitsnotebook.com/Geometry/Constructions/CCPaper.html)：將紙沿摺線翻折可理解為反射；摺線是反射軸。這成為題組模擬器的幾何基礎。
4. Kissane、Sweller、Kalyuga、Chandler（2008），[The consequences of fading instructional guidance](https://doi.org/10.1080/01443410802322069)：初學者可先藉由範例獲得引導，再逐步減少引導。網站因此採「先作答、再每次揭露一層」而非一口氣直接給完整圖。

## 檔案結構

```text
index.html             # 語意化結構、對話框與練習區
styles.css             # 響應式版面、視覺系統、鍵盤焦點與減少動態效果
app.js                 # 題組互動、SVG 繪圖、作答/逐步解答、localStorage
puzzle-data.js         # seed 程序生成、難度曲線、正解與干擾選項
paper-fold-engine.js   # 平面折紙、鏡射與摺痕回映模擬器
svg-geometry.js        # SVG 座標邊界檢驗工具
package.json           # 測試指令與 Playwright 依賴
TESTING.md             # 測試範圍與最後一次執行紀錄
tests/                 # unit / integration / e2e 測試
```

> 備註：本模擬器針對本題型使用「平面折疊」假設：每次折線都是直線，且移動側完整鏡射到保留側。它精確追蹤本題組的層數、折線與鏡像位置；不試圖模擬紙張厚度、彈性或任意曲面摺紙。
